Du PDF à la page de wiki, sans rien faire

Tu déposes. Le reste se fait tout seul, et rien n'est écrit sans être vérifié.

Dépôt

Glisser-déposer sur une page web, une matière au choix.

Lecture

Docling extrait le texte (OCR compris) et le plan est lu dans le PDF : chapitres, diapos-intercalaires.

Rédaction

Claude range chaque notion à sa place et complète les pages qui existent déjà.

Contrôles

Page raccourcie, section supprimée, mauvais dossier : refusé et mis de côté. Rien n'est écrasé.

Wiki

Un commit Git par cours, et la page apparaît dans Wiki.js quelques secondes après.

Demande. Révise.

Une fois tes cours dans le wiki, demande une fiche, des exercices ou un QCM : Claude ne s'appuie que sur tes pages, et cite lesquelles. (Démo simulée.)

Installé en 5 commandes

Il faut Docker et un abonnement Claude (ou une clé API). Linux, Windows, Mac.

$ git clone https://github.com/Kettelios-dev/slide2wiki.git && cd slide2wiki
$ cp .env.example .env
$ docker compose build
$ docker compose run --rm --entrypoint claude app setup-token   # puis colle le jeton dans .env
$ docker compose up -d   # → http://localhost:8000

Questions

Ça marche avec n'importe quel cours ?

Diapos et polycopiés en PDF, de toute matière. Le plan est détecté quand le PDF en a un (intercalaires, sommaire) ; sinon le cours est découpé en blocs. Les PDF scannés passent par l'OCR.

Et si Claude se trompe ?

Il ne peut ni écraser ni raccourcir une page : les contrôles le refusent et mettent sa version de côté. Chaque cours est un commit Git, annulable en une commande. Et ses doutes sont listés dans le rapport.

Je peux corriger les pages moi-même ?

Oui, dans l'éditeur de Wiki.js ou dans les fichiers Markdown. Une page modifiée pendant qu'un cours est intégré n'est jamais écrasée.

Ça coûte combien ?

Rien de plus que ton abonnement Claude : un cours de 80 diapos, c'est 2 appels d'environ 10k tokens. Chaque appel est noté dans un fichier pour suivre la consommation.
